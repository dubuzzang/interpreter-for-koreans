- **11개 언어**(한국어 · 튀르키예어 · 영어 · 일본어 · 중국어 간체 · 중국어 번체 · 베트남어 · 태국어 · 러시아어 · 아랍어 · 프랑스어)끼리 어느 쪽으로든 통역합니다. 중국어 **간체(zh, 중국 본토)** 는 타오바오·1688 판매자와, **번체(zh-TW, 대만 · 홍콩)** 는 대만 글자 · 낱말(計程車 · 捷運)과 대만 보통화 목소리로. **아랍어는 오른쪽에서 왼쪽(RTL)** 으로 씁니다 — 화면 언어가 아랍어면 화면 전체가 뒤집히고, 다른 화면에서는 아랍어 말풍선 · 줄만 RTL로 보입니다(v1.6.0).
- **언어 설정**: 오른쪽 위 🌐 버튼(예: `🌐 KO`)을 누르고 한국어 · Türkçe · English · 日本語 · 简体中文 · 繁體中文 · Tiếng Việt · ภาษาไทย · Русский · العربية · Français 중에서 고르면, 새로 고침 없이 화면 전체가 그 언어로 바뀌고 이 기기에 저장됩니다(설정 → "언어 / Language"도 같음). 고른 언어가 **'나'의 언어**가 됩니다 — 대화·마주 보기의 '나' 버튼(받아쓰기 · 번역 · 읽어 주기), 글 번역의 기본 방향, 표현집의 내 말 쪽, 기록 표시. 상대 언어는 나머지 열 언어 중에서 고릅니다(상대가 새 내 언어와 같아지면 서로 바꿈).
  - 처음 쓰는 사람: 브라우저 언어가 11개 언어 중 하나면 그 언어(zh-TW · zh-HK · zh-Hant는 번체, 그 밖의 zh는 간체), 아니면 English. 이미 쓰던 사람(저장된 설정·기록이 있음)은 한국어 그대로.
  - 화면 문구는 언어마다 `public/js/i18n/<code>.js`(한국어 사전 `ko.js`가 기준)에 있습니다. 서버는 한국어 오류 문장과 함께 오류 코드(`code`)를 보내고, 화면은 코드로 고른 언어 문장을 보여 줍니다.
- **읽는 법**은 보는 사람이 읽을 수 있는 글자로 보여 줍니다.

  | 보는 사람 | 읽는 법 |
  |---|---|
  | 한국어 사용자 | **한글 발음** — 튀르키예어(Merhaba → 메르하바) · 일본어(こんにちは → 곤니치와) · 중국어 간체/번체(你好 → 니 하오 + 병음 Nǐ hǎo) · 베트남어(Phở bò → 퍼 보) · 태국어(ขอบคุณ → 컵쿤) · 러시아어(Спасибо → 스파시보) · 아랍어 · 프랑스어(Bonjour → 봉주르). 영어는 적지 않음 |
  | 그 밖의 사용자 | 라틴 문자가 아닌 언어에 **로마자** — 한국어(안녕하세요 → Annyeonghaseyo) · 일본어(Konnichiwa) · 중국어(병음) · 태국어(khɔp-khun) · 러시아어(Spasibo) · 아랍어. 라틴 문자 언어(튀르키예어 · 영어 · 베트남어 · 프랑스어)는 적지 않음. 간체 ↔ 번체 사용자끼리도 적지 않음 |

  읽는 법은 언어마다 같은 길(`public/js/reading.js` READERS + `public/js/read/<code>.js`)로 만듭니다. 글만 보고 정할 수 있는 언어(튀르키예어 · 한국어 · 베트남어 · 러시아어 · 프랑스어)는 화면에서 바로, 글자만으로는 소리를 알 수 없는 언어는 서버(`/api/sound`)에서 소리 표기를 받아 바꿉니다 — 일본어 → 히라가나 읽기, 중국어 → 병음(음절 수 = 한자 수인 답을 고름), 태국어 · 아랍어 → 로마자 소리 표기. 한글 발음은 국립국어원 외래어 표기법의 각 언어 표를 따릅니다(Běijīng → 베이징, Nha Trang → 냐짱, Москва → 모스크바, กรุงเทพ → 끄룽텝).
  표현집은 서버를 거치는 언어의 소리 표기(히라가나 · 병음 · 태국어/아랍어 로마자)를 미리 넣어 두어 인터넷 없이도 보입니다. 마주 보기의 각 절반도 그쪽 사람 기준입니다.
- **업데이트 버튼**: 새 버전을 배포하면 열려 있는 앱 위에 "업데이트" 알림이 뜨고(저장된 언어로), 누르면 바로 바뀝니다(설정 → 업데이트 확인). 알림 코드는 `index.html` 안에 있어서(페이지는 늘 새로 받음) 예전 버전 앱에서도 뜹니다.
- **자동 감지**(글 번역 · 사진 줄): 한글 → 한국어, 가나가 있으면 일본어, 한자만 있으면 간체 · 번체 · 일본 글자체를 세어(這·們 → 번체, 这·们 → 간체, 駅·円 → 일본어, 어느 쪽도 아니면 대화 상대 쪽), 타이 문자 → 태국어, 키릴 문자 → 러시아어, 아랍 문자 → 아랍어, 라틴 문자는 베트남어 글자(ơ · ư · đ · 성조) · 프랑스어 글자(é · à · œ) · 튀르키예어 글자(ğ · ı · ş)와 흔한 낱말로 베트남어 · 프랑스어 · 튀르키예어 · 영어를 가릅니다.
- **사진 번역은 그림에 없는 글자 · 가격을 만들지 않게** 합니다: 지시문(원문 그대로 · 보이는 글자만 · 같은 줄에 인쇄된 가격만 붙이고 모르면 따로 · 환율 환산 금지) + 서버 검사(`lib/photo-core.mjs`: 번역에 원문에 없는 숫자 → 번역을 빼고 표시, 엉뚱한 언어 · 되풀이 · 빈 답 · 잘린 JSON 거르기, 글자가 없으면 요약도 없음). 그래도 AI가 읽은 글자라 화면에 "가격 · 숫자는 사진과 맞춰 보세요"를 늘 띄웁니다.
- **답장 추천 · 합의 내용 요약은 숫자를 지어내지 않습니다**: 서버(`lib/assist-core.mjs`)가 답 안의 숫자(아라비아 숫자 · 한자 숫자 一百五 · 한국어 백 개/두 개/이틀 · 튀르키예어 yüz elli · 영어 two hundred · 일본어 ふたつ · 베트남어 hai trăm năm mươi nghìn · 50k · 태국어 สองร้อยห้าสิบ · 타이 숫자 ๑๕๐ · 러시아어 двести пятьдесят · полтора · 아랍어 خمسين · 아랍 숫자 ٢٥٠ · 프랑스어 quatre-vingts · 14,50)를 값으로 바꿔, 대화(원문 · 번역)에 나온 값이 아니면 그 답(요약은 그 칸)을 버립니다. ○○ · ___ · XX 같은 빈칸도 버립니다. 답장 추천은 설정에서 끌 수 있습니다.
- 말투: 존댓말 / 반말 — 번역되는 쪽 언어에 맞게(한국어 존댓말·반말, 일본어 です·ます·タメ口, 튀르키예어 siz·sen, 러시아어 вы·ты, 프랑스어 vous·tu, 중국어 您·你, 베트남어 · 아랍어 공손한 말·편한 말, 영어는 영향 없음). 태국어는 말하는 사람의 성별을 몰라 성별 말끝(ครับ/ค่ะ)을 넣지 않습니다(모델이 붙이면 지움). 최근 대화를 맥락으로 함께 보내 대명사·생략을 자연스럽게 옮깁니다.

### 번역 엔진 (2026-10-08 비교)

한·튀·영 예문 7개를 모델마다 번역해 비교했습니다.

| 모델 | 결과 |
|---|---|
| **Gemma 4 26B (생각 끔)** | 가장 자연스러움, 1~1.5초 → 기본 |
| Gemma 4 (생각 켬) | 5~17초, 빈 답도 나옴 → `chat_template_kwargs.enable_thinking=false` 필수 |
| Qwen 3.8 27B | 자연스럽지만 튀르키예어 격조사 실수(otobüsü binmek), 1~29초로 들쭉날쭉 |
| Llama 3.3 70B | 무난, 고유명사 실수(Taksim → 택심) → 1차 예비 |
| Mistral Small 3.1 | 가장 빠름(1초), 튀르키예어 문법 실수가 더 많음 → 2차 예비 |
| m2m100 1.2B (번역 전용) | 뜻이 틀림(매워요 → "Bu çok basit") → **쓰지 않음**. 틀린 통역보다 오류 안내가 낫다 |

모델마다 9~12초 제한, 실패·빈 답·글자 체계가 틀린 답이면 다음 모델로 넘어갑니다. Workers AI 무료 사용량(하루 10,000 뉴런)을 다 쓰면 "오늘 무료 번역 한도" 안내가 나옵니다.

한 번에 쓰는 양(2026-10-12 Gemma 4, Workers AI 응답의 `usage`): 번역 약 220~310토큰 ≈ **2~3.4 뉴런**, 답장 추천 약 420~520토큰 ≈ **5.5~7 뉴런**(상대 말마다 한 번), 합의 내용 요약 약 340~610토큰 ≈ **4~8.5 뉴런**(공유할 때 켠 경우만). 답장 추천을 켜 두면 대화 하나에 드는 AI 사용량이 대략 2배가 됩니다.

### 사진 번역 엔진 (2026-10-12 비교)

같은 지시문으로 실제 그림(타오바오 영상 프레임 · 샤오홍슈 요리 사진 · 160px 썸네일 · 글자 없는 사진)과 HTML로 만든 메뉴판(튀르키예어 · 일본어 · 영어) · 긴 상세 이미지를 읽혀 비교했습니다. 그림은 `messages`의 `image_url`(data URL)로 줍니다 — 최상위 `image`로 주면 그림을 못 보고, Qwen은 그때 없는 글을 지어냈습니다.

|---|---|---|
| **Gemma 4 26B (생각 끔)** | 메뉴 가격 · 중국어 요리 사진 · 상세 이미지 · 썸네일 거의 정확, 글자 없는 사진은 빈 답 → **기본** | 7~33 뉴런 · 1~25초 |

- 긴 그림(750×4423)을 통째로 줄여 보내면(271×1600) 흐린 글자를 그럴듯하게 바꿔 썼습니다(节假日顺延 → 除外) → 화면에서 2:1 정도 조각으로 겹치게 잘라 보냅니다.
- "메뉴와 가격을 한 줄로" 지시로는 설명 줄이 낀 메뉴에서 가격이 한 줄씩 밀렸습니다(온도 0에서도 4번 중 2번) → "같은 줄에 인쇄된 가격만 붙이고, 모르면 가격을 따로"로 바꿨습니다.
- **사용량 (Gemma 4, 화면이 보내는 크기 그대로 31장)**: 한 장 평균 **약 18 뉴런**(글자 없음 7 · 영상 프레임 11 · 사진 18 · 빽빽한 메뉴판 30), 평균 9.5초. 그림 한 장은 입력 약 790토큰(그림 약 280 + 지시문)으로 거의 같고, 나머지는 읽은 글의 양(출력 토큰)에 따라 늡니다. 긴 상세 이미지는 조각 수만큼(750×4423 → 4조각 합 약 90 뉴런 + 요약 3~5).
- 무료 사용량(하루 10,000 뉴런, 번역 · 추천 · 요약과 **같이** 씀)으로 치면 사진만 하루 약 **550장**(메뉴판만이면 약 330장, 긴 상세 이미지만이면 약 110장)입니다.

### 무료 요금제 안전장치 (v1.6.0)

Cloudflare 무료 요금제는 Workers AI를 하루(UTC) **10,000 뉴런** 넘게 쓰면 다음 UTC 0시(한국 오전 9시)까지 계정의 Workers AI가 멈춥니다(4006) — 번역까지 모두 멈춥니다. 그래서 하루 사용량을 세어 두고, 많이 쓴 날에는 없어도 되는 기능부터 쉽니다.

- **세기**: 모든 AI 호출(`lib/usage.mjs`의 `runAI`)이 쓴 뉴런을 하루 한 줄로 D1(`tercuman-usage`, 표 `ai_usage`)에 더합니다. 응답에 뉴런이 있으면 그것, 없으면 토큰 수 × 모델 단가(Gemma 4 입력 0.0091 · 출력 0.0273, Llama 3.3 70B 0.0267 · 0.205, Mistral Small 3.1 0.032 · 0.0505 뉴런/토큰, Whisper 1분 46.7 뉴런), 토큰 수도 없으면 넉넉히 어림합니다. 기록은 응답을 늦추지 않게 뒤에서(`waitUntil`) 하고, 표는 처음 쓸 때 만듭니다. KV는 무료 쓰기가 하루 1,000번이라 쓰지 않습니다(D1은 하루 10만 줄). 개발 서버에서 17번 불러 실제 약 50 뉴런을 쓸 때 카운터는 57.5 뉴런으로 조금 넉넉하게 셌습니다.
- **쉬기**: 오늘(UTC) 센 값이 **7,000 뉴런**(70%, `wrangler.toml`의 `USAGE_PAUSE_NEURONS`) 이상이면 답장 추천 · 합의 요약 · 사진 번역 · 사진 요약은 AI를 부르지 않고 `503 { code: 'paused', until }`으로 답합니다. **번역 · 읽는 법 · 받아쓰기는 계속됩니다.** UTC 0시가 지나면 저절로 다시 됩니다.
- **화면**: 답장 추천은 조용히 숨기고(다시 될 때까지 부르지 않음), 사진 · 요약은 "오늘은 사용량이 많아 이 기능을 쉬어요 — 오전 9:00에 다시 돼요."를 그 사람 화면 언어 · 지역 시각으로 보여 줍니다.
- 사진 번역의 예비 모델(Mistral)은 껐습니다. 기본 모델이 바쁘면 한 번 더 부르고, 그래도 안 되면 "잠시 뒤 다시 해 주세요"로 안내합니다. 번역의 예비 모델 순서는 그대로입니다.
- D1이 없거나 오류면 세기 · 쉬기 모두 건너뜁니다(번역을 막지 않음).
- **주의**: 개발 · 시험(`npm run dev`는 내 PC의 D1에 셉니다) · 대시보드 · 같은 계정의 다른 앱도 같은 한도를 쓰지만 이 카운터에는 안 잡힙니다 → 실제보다 적게 셀 수 있어 문턱을 낮게 잡았습니다. 번역만으로 10,000을 넘기면 여전히 멈춥니다.
- 오늘 사용량 보기: `npx wrangler d1 execute tercuman-usage --remote --command "SELECT day, round(neurons, 2) AS neurons, calls FROM ai_usage ORDER BY day DESC LIMIT 7"`

## 개발

```powershell
npm test                 # 단위 테스트 (가짜 AI로 API까지)
npm run dev              # 로컬 서버 http://127.0.0.1:8788 (AI는 Cloudflare 계정으로 실제 호출)
npm run build:sw         # public/ 파일을 바꾼 뒤 서비스 워커 갱신
npm run deploy           # Cloudflare Pages 배포 (wrangler 로그인 필요)
```

- 버전을 올릴 때: `package.json`·`public/js/version.js`·`CHANGELOG.md`를 함께 바꾸고 `npm run build:sw`.
- 화면 문구를 더할 때: `public/js/i18n/`의 11개 사전에 같은 키로 넣고 `t('키')`로 씁니다. 테스트가 사전의 키·빈 문구·`{채울 자리}`가 같은지, 화면 코드에 한국어 문장을 직접 쓰지 않았는지 확인합니다.
- 언어를 더할 때(v1.6.0 공통 틀): `public/js/lang.js` LANGS 한 줄 → `i18n/<code>.js`(화면 글자) · `phrases/<code>.js`(표현집, 열쇠 = 분류|한국어) · `read/<code>.js`(읽는 법) · `lib/langs/<code>.mjs`(서버: 말투 · 글자 규칙 · 결과 점검 · Whisper · 숫자 · 소리 표기 · 사진 읽기 — 규칙은 `lib/langs/index.mjs` 설명) · index.html 업데이트 알림 한 줄. `tests/langs.test.mjs`가 빠진 자리를 찾습니다.
- GitHub Actions는 테스트만 돌립니다. 배포는 번역 API(Pages Functions + Workers AI)가 필요해서 Cloudflare Pages로만 합니다.

## 개인정보

말한 내용과 글은 번역 · 인식 · 답장 추천 · 요약을 위해 Cloudflare Workers AI로 보내고, 서버에 저장하지 않습니다. 사진 번역의 사진도 화면에서 줄인 뒤 Workers AI로 보내 읽기만 하고 저장하지 않습니다. 통역 기록 · 설정 · 내 표현은 이 기기(localStorage)에만 남습니다. 서버(D1)에는 하루 AI 사용량 합계(뉴런 · 횟수)만 남고 말한 내용은 남지 않습니다. 공유는 사용자가 고른 앱(카톡 · 메일)으로 직접 보내는 것이고, 이 앱 서버를 거치지 않습니다.
